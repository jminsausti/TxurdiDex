# Auditoría técnica y didáctica de TxurdiDex

## 1. Resumen ejecutivo

La secuencia de los apuntes admite un catálogo Pokémon local que evolucione a búsqueda, componentes, HTTP, rutas y estado compartido. Conviene conservar las demostraciones pequeñas de JavaScript, Vue Router y Pinia, así como las prácticas autónomas. El tema 7 organiza cinco ejercicios en tres aplicaciones. La secuencia de personajes de los ejercicios 3–5 forma una aplicación progresiva autónoma ([7.1 ES](../Vuejs_Apuntes_es-eu/docs/es/7-proyecto/7.1-estructura.md), [7.2 ES](../Vuejs_Apuntes_es-eu/docs/es/7-proyecto/7.2-ejercicios.md)).

ProductoGest proporciona el modelo de versiones incrementales. La Pokédex ofrece patrones de catálogo, comunicación y consumo de API en una aplicación que instala Router y Pinia desde su arranque. Se propone implementar un hilo acumulativo propio, mantener el catálogo público de lectura y valorar una colección local de escritura para el equipo. Los cortes con mayor rediseño son 4.3 (HTTP y API local) y 6.4 (equipo y estado compartido).

## 9. Cobertura de Vue y HTTP

Los fundamentos quedan en temas 1–2, la separación de responsabilidades en 3, asincronía y estados de interfaz en 4, parámetros y navegación en 5, y estado compartido en 6. Los capítulos de Router y Pinia conservan sus proyectos pequeños. La clase dinámica de favorito puede aparecer en 2.5 después de la búsqueda como ampliación. El modelo de equipo cubre el cambio de origen de datos sin introducir estado global en tema 4.

Validar en la versión elegida qué devuelve cada método y qué tipo tiene el ID. JSON Server se usaría como servidor de aula, con datos de práctica y dos terminales o comandos documentados.
